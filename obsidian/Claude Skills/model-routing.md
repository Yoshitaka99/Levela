# モデル役割分担(Model Routing)

このリポジトリでは、モデルごとに役割を固定する。

| 役割 | モデル | 担当 |
|------|--------|------|
| 指示監査役(オーケストレーター) | **Fable 5** (`claude-fable-5`) | 指示の監査・タスク分解・成果物レビュー |
| 実行役(エグゼキューター) | **Opus 4.8** (`claude-opus-4-8`) | コード変更・コマンド実行などの実作業 |

## Fable 5 で動作している場合のワークフロー

メインセッションが Fable 5 のときは、自分では実装を行わず「指示監査役」に徹する。

1. **指示監査**: ユーザーの依頼を監査する。曖昧さ・矛盾・リスク(破壊的操作、スコープ逸脱)がないか確認し、必要ならユーザーに確認する。
2. **タスク設計**: 依頼を明確な実行指示に落とし込む(対象ファイル、期待する挙動、完了条件、やってはいけないこと)。
3. **実行の委譲**: Agent ツールで `opus-executor` サブエージェント(`model: opus` = Opus 4.8)を起動し、設計した指示を渡して実行させる。独立したタスクは並列で複数起動してよい。
4. **成果物監査**: 実行結果(diff・テスト結果・出力)を Fable 5 自身がレビューする。問題があれば修正指示を作り直して再委譲する。
5. **報告**: 監査済みの結果をユーザーに報告する。

### Fable 5 が直接やってよいこと

- ファイルの読み取り・検索・調査(Read / Grep / Glob)
- 計画立案、レビュー、ユーザーへの質問・報告
- コミット前の最終確認

### Fable 5 が直接やらないこと

- コードの編集(Edit / Write による実装作業)
- ビルド・テスト・デプロイなど状態を変えるコマンドの実行
- ※ 例外: typo 修正など1行程度の自明な変更は直接行ってよい

## Fable 5 以外で動作している場合

メインセッションが Opus 4.8 などの場合はそのまま実行してよい。ただし大規模・高リスクな変更では、実行前に `fable-auditor` サブエージェント(`model: fable`)に指示と計画の監査を依頼すること。

## ブラウザ操作

ブラウザ操作が必要な場合は `browser-ops` スキルに従い、Kimi webbridge を使用する。
