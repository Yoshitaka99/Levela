# 用途別の依頼文テンプレート

該当するものを選び、`「」` の中身を差し替えて `/hyperframes` に渡す。すべて **`frame.md` を置いたフォルダで実行する前提**（無い場合は `brand-frame.md` のスタイル段落を末尾に添える）。

尺・比率・言語は必ず明記する。書かなかった項目はエージェントが決めるので、そこがブレる場所になる。

## 目次

1. 解説動画（テーマだけ渡す）
2. 実績カード・数字の短尺
3. 告知・ローンチ（音ハメ）
4. 記事 / note の動画化
5. サービス・サイト紹介
6. 既存の喋り動画に図解を重ねる
7. GitHub PR のレビュー動画
8. 縦型ショート（9:16）
9. 週次ニュースまとめ

## 1. 解説動画（テーマだけ渡す）

顔出しなし・撮影なし・素材なし。リサーチ、台本、ナレーション音声、動くタイポグラフィ、図解、字幕、BGM、効果音、レンダリングまで一括で面倒を見る。**最も出番が多い。**

```
/hyperframes
45秒の解説動画を作ってください。

テーマは「ここに記事の主張や手順を貼る」です。
内容に関わる数字や固有名詞は、Web検索で事実確認をしてから使ってください。
確認できなかった数字は使わず、その旨を報告してください。

ナレーションは日本語、字幕あり。
サイズは1920x1080。
デザインはframe.mdに従ってください。
```

尺は 45 秒に限らず 60 秒でも 90 秒でも指定できる。**最初のうちは短め**の方が修正の練習がしやすい。

## 2. 実績カード・数字の短尺

10 秒以下、ナレーションなし、動きそのものがメッセージ。**入力が一文で済むので、最初の 1 本に最適。**

```
/hyperframes
5秒の実績カードを作ってください。
「フォロワー10,000人達成」の数字が0からカウントアップして、
達成日をカードの下に小さく入れてください。
サイズは1080x1080。
デザインはframe.mdに従ってください。
```

- **エフェクト名を指定しない。** 「ズームで」「バウンドさせて」は言わなくていい。内容と順番だけ言えば動きは最適化される。
- 実データを取得させる場合は「数字は◯◯から取得して、取得日を画面に入れて」と書く。数字の透明性が上がり、実績報告の信頼感が変わる。
- 背景を透明で書き出せば、手持ちの動画に重ねる素材になる。必要なら「背景透過で書き出して」と添える。

## 3. 告知・ローンチ（音ハメ）

曲を渡すと BPM・拍の位置・盛り上がりの構造・ドラムのフィルまで解析した設計図を作り、すべてのカットをそれに従わせる。音楽の知識ゼロで音ハメが成立する。

```
/hyperframes
この曲から30秒の告知動画を作ってください。
（音声ファイルのパスを指定）

内容は「告知したい商品やイベントの情報」です。
すべてのカットはビートに同期させて、一番の見せ場は曲の盛り上がりに合わせてください。
サイズは1080x1920。
デザインはframe.mdに従ってください。
```

商品ローンチ予告、イベント告知、月次の振り返りと相性がいい。**BGM 選びのセンスがそのまま動画の質になる**ので、音源だけはこだわって選ぶ。

## 4. 記事 / note の動画化

既にあるストックが動画になる。1 つのテーマから記事・ポスト・動画の 3 展開ができる。

```
/hyperframes
60秒の解説動画を作ってください。

元になる記事の本文をそのまま貼ります：
---
（記事全文）
---

この記事の主張を3つのポイントに整理して、それぞれを図解で見せる構成にしてください。
記事に出てくる数字は事実確認をしてから使ってください。
冒頭5秒で「誰の何の悩みが解決するか」を言い切ってください。

ナレーションは日本語、字幕あり。サイズは1920x1080。
デザインはframe.mdに従ってください。
```

---

## 5. サービス・サイト紹介

```
/hyperframes
https://紹介したいサイト.com から45秒の紹介動画を作ってください。

実際のサイトの内容を読み込んで、提供価値を3点に絞ってください。
サイトに書かれていない機能や実績を追加しないでください。
最後の5秒はCTA（「詳しくはプロフィールのリンクから」）で締めてください。

ナレーションは日本語。サイズは1920x1080。
デザインはframe.mdに従ってください。
```

「サイトに書かれていないことを追加しない」は入れておく。**紹介動画は誇張が最も事故になりやすい。**

## 6. 既存の喋り動画に図解を重ねる

喋りに同期して、数字がカウントアップしたり固有名詞の説明カードが差し込まれたりする。ビジネス系 YouTube の手の込んだ編集がそのまま自動化される。

```
/hyperframes
この動画に、話している内容へ同期した図解カードとテロップを重ねてください。
（動画ファイルのパスを指定）

重要な数字はカウントアップで見せて、字幕は画面下部に配置。
話者の顔に図解が被らないようにしてください。
デザインはframe.mdに従ってください。
```

字幕だけを入れたい場合は「字幕だけを入れてください。映像自体は変更しないでください」と書く（別のワークフローに振り分けられる）。

## 7. GitHub PR のレビュー動画

PR のタイトル・説明・コード差分・コミット履歴・レビュアーの状況まで読み込み、変更規模に見合った尺に仕立てる。画面に出るコードはスクリーンショットではなく本物の差分。

```
/hyperframes
このPRのレビュー用ブリーフィング動画を作ってください。
（PRのURL）

レビュー待ちの状態です。60秒前後、日本語ナレーションで。
変更の目的、影響範囲、レビュアーが特に見るべき箇所、の順で構成してください。
デザインはframe.mdに従ってください。
```

## 8. 縦型ショート（9:16）

```
/hyperframes
45秒の縦型動画を作ってください。サイズは1080x1920。

テーマは「ここに告知したい商品や企画の説明」です。
冒頭2秒で結論を言い切ってください。
重要な要素は画面の上下15%を避けて、中央に収めてください（SNSのUIが被るため）。
文字は1行15字以内、同時表示は2行までにしてください。

ナレーションは日本語、字幕は大きめ。
デザインはframe.mdに従ってください。
```

セーフエリアと文字量の指定は縦型では毎回入れる。**この 2 行があるかどうかで縦型の完成度が決まる。**

## 9. 週次ニュースまとめ

一度型を作れば、あとは中身を差し替えるだけのルーティンになる。継続が仕組みで担保される。

```
/hyperframes
30秒のニュースまとめ動画を作ってください。

「対象分野」の今週のニュースをWeb検索でリサーチして、重要な3件を選んでください。
各ニュースは1枚のカードで、見出し・要点1行・出典元の名前を入れてください。
各カードの表示は7秒前後。最後に「詳細はプロフィールから」で締めてください。
出典が確認できないニュースは採用しないでください。

サイズは1080x1920。ナレーションは日本語。
デザインはframe.mdに従ってください。
```

---

## 型を作るときの共通ルール

- **冒頭 2〜5 秒で結論を言い切らせる。** SNS ではここで離脱が決まる。
- **最後の 1 枚は止め絵で 0.5 秒以上残す。** ロゴか CTA。切れ味よく終わると情報が残らない。
- **事実確認を明示的に頼む。** 「確認できなかったら使わずに報告して」まで書くと、埋め合わせの捏造が止まる。
- **「〜しないでください」を 1〜2 個入れる。** やってほしいことより、やってほしくないことの方が指示として効く。
