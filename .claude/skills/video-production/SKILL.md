# 動画制作ディレクション（HyperFrames 運用）

HyperFrames は **HTML を 1 フレームずつ撮影して MP4 にする**フレームワーク（HeyGen 製 / Apache-2.0 / ローカル完結・レンダー課金なし）。タイムラインを触る代わりに、言葉で指示して HTML を書かせ、決定論的にレンダリングする。

このスキルは HyperFrames の**使い方を再実装しない**。作り方の正解は公式スキル群（`/hyperframes` 以下）が持っている。ここが担保するのは、**誰がいつ頼んでも同じ水準で「綺麗」に仕上がるための前後の工程**——ブランドの固定、依頼文の情報密度、目視での品質ゲート、修正の回し方。

## なぜこの手順なのか

AI が作った動画が安っぽく見える原因は、性能ではなく**入力の欠落**にある。ブランドを知らなければ世界の平均値が出てくるし、尺・比率・トーンを書かなければエージェントが勝手に決める。逆に言えば、渡す情報を型で固定するだけで品質は安定する。だから毎回この順で進める。

---

## Step 0 — 環境と現在地の確認

```bash
bash .claude/skills/video-production/scripts/check-env.sh
```

Node 22+ / FFmpeg / HyperFrames スキル / 日本語フォント を点検して、足りないものだけを報告する。詰まったら `references/setup.md`。

未インストールなら、動画用フォルダを作ってその中で：

```bash
npx skills add heygen-com/hyperframes --all --full-depth
```

`--full-depth` はリポジトリ最新版から取るための指定（付けないと数時間古いコピーが入ることがある）。

**日本語動画では日本語フォントの確認が最重要。** レンダリングはヘッドレス Chrome が行うので、OS にフォントが無ければ本文が豆腐（□□□）になる。ここだけは事前に潰しておく（`references/setup.md` 参照）。

## Step 1 — ブランドを 1 ファイルに固定する

**このステップを飛ばした動画は、どれだけ指示を足しても「それっぽい何か」で止まる。** 3 本目あたりから差が決定的になるので、初回だけ 10 分かける。

プロジェクトフォルダに設計仕様ファイルを置く。読み込みの優先順位は `frame.md` → `design.md` → `DESIGN.md` で、**小文字の `frame.md` を推奨**（動きの定義まで含む上位版）。置いてあるだけで、そのフォルダで作る動画すべてに自動適用される。

作り方は 3 通り。詳細とプロンプト全文は `references/brand-frame.md`：

1. **サイトがある** → ライブ HTML と実際に読み込まれている CSS から抽出させる（推測禁止・出典必須のプロンプトを使う）
2. **サイトがない** → 普段使っている色コード・フォント・口調を伝えて同じ形式に整えてもらう
3. **既に DESIGN.md がある** → モーション言語を足して `frame.md` に拡張する

作ったら **20 秒のブランドリールを 1 本レンダーして検証する**。仕様書を読むより、動いているものを見る方が違和感に早く気づく。

---

## Step 2 — 依頼文を型に通してから渡す

思いついた文をそのまま投げない。以下が**毎回埋める枠**で、欠けた項目はエージェントが勝手に決める＝ブレる場所になる。

```
1. 何の動画か（用途・視聴者・どこに出すか）
2. 尺（秒数を明記。書かないとテンポが決まらない）
3. 解像度と比率（16:9=1920x1080 / 9:16=1080x1920 / 1:1=1080x1080）
4. 中身（台本があれば全文、なければ主張・手順・数字）
5. 事実の扱い（数字と固有名詞は要検索確認、出典と取得日を画面に出すか）
6. デザイン（frame.md に従う、と書く。無い場合はスタイル段落を添える）
7. ナレーション・字幕の言語と有無
```

`frame.md` が無い状態で作る場合は、代わりに**スタイル段落**を添える。順番まで含めて型がある——スタイル名／hex 込みの正確なパレット／アートの方向性／ものの動き方／場面転換／雰囲気を一言。テンプレートは `references/brand-frame.md`。

用途別（解説・音ハメ・実績カード・PR・告知・縦型など）の完成済み依頼文は **`references/brief-templates.md`** に置いてある。まずここから該当するものを選び、中身だけ差し替える。

### 指示の粒度で外さないコツ

- **エフェクト名を指定しない。** 「ズームで」「バウンドさせて」は言わなくていい。伝えたい内容と見せたい順番だけ言えば、動きの設計はエージェント側が最適化する。指定するほど不自然になる。
- **数字は盛らせない。** 実データを取得させ、いつ時点かを画面に刻ませる。これは信頼性の問題であると同時に、後から燃える事故を構造的に防ぐ。

## Step 3 — ルーティングは `/hyperframes` に任せる

```
/hyperframes
（Step 2 で組み立てた依頼文）
```

**必ず `/hyperframes` から入る。** これがルーター役で、依頼内容から適切な専門ワークフローへ振り分ける。個別スキルを直接指名すると、そのスキルの入出力契約に合わない依頼を無理に通してしまう。どれを使うか覚える必要はない。

参考（振り分け先の一覧。指名するためではなく、見当がつくように）：

| 作りたいもの | 行き先 |
| --- | --- |
| テーマだけ渡す解説動画（顔出しなし） | `/faceless-explainer` |
| サイト・製品・アプリの紹介 | `/product-launch-video` |
| 曲のビートに同期した動画 | `/music-to-video` |
| 10 秒以下・ナレーションなしの短尺（実績カード、数字、ロゴ） | `/motion-graphics` |
| GitHub PR の解説 | `/pr-to-video` |
| 既存の喋り動画に図解を重ねる | `/talking-head-recut` |
| 既存の喋り動画に字幕だけ入れる | `/embedded-captions` |
| 上記に当てはまらない・長尺・複数シーン | `/general-video` |

初回は雛形作成に時間がかかる。完成を待たずに次の工程へ進まないこと。

## Step 4 — レンダー前に必ず目で見る

ここが「綺麗さ」の実質的な分かれ目。**書き出す前に静止画で確認する。** 動画を最後まで再生して確認するより速く、崩れは静止画で見つかる。

```bash
npx hyperframes check              # 構成の検証
npx hyperframes snapshot           # 主要時点のフレームを画像で書き出し
```

書き出した画像を **Read ツールで実際に開いて見る**。「checkが通った」は「綺麗である」を意味しない。日本語の改行位置、文字の被り、セーフエリアからのはみ出しは、目でしか見つからない。

確認項目の全リストは **`references/quality-checklist.md`**。特に効くのは以下：

- **日本語組版** — 変な位置での改行、行頭の句読点、豆腐（□）。1 行 15〜20 字、短尺は同時 2 行まで。
- **セーフエリア** — 縦型は上下約 15% に SNS の UI が被る。重要な要素は中央 70% に収める。
- **空白フレームゼロ** — 前の要素が消えきる前に次が出始めているか。一瞬でも画面が空くと素人臭くなる。プロの現場が最も気を使う箇所。
- **コントラスト** — 本文 4.5:1 以上。背景映像の上のテロップが最も破綻しやすい。
- **色の一致** — `frame.md` の hex と 1px もズレていないか。

継続的なプレビューが要るときは `npx hyperframes preview`（保存即反映）。納得してから：

```bash
npx hyperframes render
```

初回はレンダリング用のブラウザ部品を落とすので時間がかかる。2 回目以降は速い。

---

## Step 5 — 修正は「一文ずつ」通す

HyperFrames の本領は 1 本目ではなく直しのループにある。ローカル完結なので**何回やり直しても追加費用ゼロ**。我慢して微妙なものを出す理由が無い。

回し方は 2 つだけ：

- **1 回の指示に 1 テーマ。** 詰め込むと意図が薄まり、直ってほしくない箇所まで動く。一文か二文投げて、返ってきたら次。これが結局いちばん速い。
- **専門用語を使わない。** イージングもキーフレームも言わなくていい。「この文字が上の行と被ってるから下に逃して」「締めのカードは 1 枚にまとめて、最後は緑のバナーで止めて」——見たままの不満と欲しい状態を言えば通る。

言い換えに詰まったときの対訳集が `references/retake-phrasebook.md`。「なんか安っぽい」のような言語化できていない違和感を、具体的な指示に落とすための表も入れてある。

修正後は **Step 4 の目視ゲートに必ず戻る。** 1 箇所直すと別の箇所のレイアウトが動くことがあるので、差分だけ見て済ませない。

---

## 使い分けと限界

**HyperFrames が強いのは、情報を伝える動画。** 解説、告知、実績報告、モーショングラフィックス。実写素材を細かく切り貼りする Vlog 的な編集は、まだ従来の編集ソフトの土俵。ここを無理に寄せると時間を溶かすので、最初に判断する。

ターミナルを使わない選択肢として HeyGen の Video Agent（ブラウザ完結・アバター対応・要アカウント）もある。無料で量産・自動化・ブランドをファイルで厳密管理したいならターミナル版、アバターに喋らせたい／今すぐ 1 本欲しいなら Video Agent。
