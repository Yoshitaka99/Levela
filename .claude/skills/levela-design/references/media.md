# 媒体別の適用

トークンは全媒体共通。**当て方**だけが変わる。

---

## Web / LP（Next.js + Tailwind v4）

このリポジトリは Tailwind v4（`@import "tailwindcss"` + `@theme inline`）と shadcn/ui（style: `radix-nova`、
baseColor: `neutral`、アイコンは lucide）で動いている。

### 導入

`assets/tokens.css` の `@theme` ブロックを `app/globals.css` に取り込むと、
`bg-paper-50` `text-ink-950` `border-ink-100` `text-brass` のようなクラスが使えるようになる。

未導入の状態で書くなら任意値で書く（`bg-[#FFFDFA]` `text-[#231815]`）。
**`slate-*` / `zinc-*` / `teal-*` / `cyan-*` は使わない** — Levelaの色ではない。
Tailwind標準色で近いのは `stone-*`（暖色系グレー）だが、`#231815` は `stone-950` より温かいので、
主要な面と文字は確定値を使う。

### 構造

```
<section>  縦余白 py-24（PC） / py-12（スマホ）
  <div>    max-w-6xl mx-auto px-6
```

- ファーストビューは `min-h-[88vh]` 前後。100vhにするとスマホのURLバーで崩れる
- カード: `rounded-xl border border-[#E7E1D8] bg-white shadow-[0_18px_36px_rgba(35,24,21,0.10)]`
- 主ボタン: `rounded-full bg-[#231815] text-white px-7 py-4 font-bold`
- 副ボタン: `rounded-full border border-[#C9BFB8] text-[#231815] px-7 py-4`

### レスポンシブは別媒体として扱う

PCで作ってスマホは「自動で入るだろう」は必ず崩れる。
最低でもこの3点を実機幅（375px / 768px / 1440px）で確認する:

- ヘッダーのメニュー（開閉、スクロール後の挙動）
- ヒーロー見出しの折り返し
- 表とグラフの横溢れ（`overflow-x: auto` を親に付ける）

Playwright が使えるなら実際に開いて確認する。目視できないまま「対応済み」と書かない。

### ダッシュボード（暗モード）

`references/brand.md` の暗モード値を使う。数値の可読性が最優先。

- 背景 `#171010` / カード `#231815` / 罫 `rgba(246,242,234,0.12)`
- KPIの数値は `#F6F2EA` + `tabular-nums`。桁を揃える
- アクセントは真鍮 `#BAA279`。**ネオン（teal/cyan）を足さない**
- 装飾（グラデーション、光彩、アニメーション）は削る方向で判断する。
  長時間見る画面では、装飾は疲労にしかならない

## スライド資料（pptx / python-pptx）

`assets/tokens.py` を import して使う。既存の `make_*_slides.py` は紺・青系で書かれているが、
**新規スライドはトークンに従う**。

### 版面（16:9 / 13.333 × 7.5 inch）

| 項目 | 値 |
|---|---|
| 左右余白 | 0.9 inch |
| 上余白 | 0.75 inch |
| 下余白 | 0.6 inch |
| タイトル位置 | 上余白から下へ |
| ノンブル | 右下、`ink-500`、11pt |

### 文字サイズ

| 役割 | サイズ | フォント |
|---|---|---|
| 表紙タイトル | 40–44pt | Yu Gothic Bold |
| 中面タイトル | 28pt | Yu Gothic Bold |
| 小見出し | 18pt | Yu Gothic Bold |
| 本文 | 14–16pt | Yu Gothic Medium |
| 注釈 | 11pt | Yu Gothic Medium |

**投影では14pt未満を使わない。** 後ろの席から読めない。
配布専用（画面で読む前提）なら12ptまで許容。どちらの用途かを `design.md` に書いておく。

### 1スライド1メッセージ

タイトルは体言止めではなく**言い切り**にする。
「売上推移」ではなく「新規は3期連続で伸びている」。
言い切れないなら、そのスライドはまだ何を言いたいか決まっていない。

### 表紙

表紙が「顔」。ここに3案分の思考を使う。
基本形: 紙背景（`#FFFDFA`）+ 墨のタイトル + 両端が消える罫 + 右下または左下にロゴ。
赤はロゴの中だけ、または1語の下線だけ。

## Artifact（claude.ai の共有ページ）

`artifact-design` スキルも併せて読む。あちらが「Artifactとしての作法」、
こちらが「Levelaとしての見た目」を決める。競合したら**ブランド値はこちらが優先**。

- 明/暗の両テーマ対応が必須。`assets/tokens.css` は
  `prefers-color-scheme` と `:root[data-theme]` の両方を含んでいるのでそのまま使える
- CSPで外部リクエストが全部落ちるので、CSSは全部インライン。Geistが読めない環境では
  `system-ui` にフォールバックする（`tokens.css` に定義済み）
- 横スクロールは表やグラフの内側に閉じ込める。ページ本体を横スクロールさせない

## 図版・画像生成

- 生成時は**参考画像を添付**し、**実写かイラストかを明示**する（`references/workflow.md` 参照）
- 生成画像に文字を焼き込まない。文字はHTML/pptx側で載せる。焼き込むと直せない・翻訳できない
- 図解（構成図・フロー図）は生成AIではなく**コードで描く**（SVG / mermaid / python-pptx）。
  線と文字がボケず、後で直せる
- 写真の上に文字を載せるときは、墨のオーバーレイ `rgba(35,24,21,0.45)` を挟む。
  写真によって可読性が変わる事故を構造的に防げる

## Markdown 文書（`docs/` 配下）

色もフォントも使えないので、**構造だけがデザイン**になる。

- 見出しは `##` から始める（`#` はタイトル1つ）。階層を飛ばさない
- 3項目以上の並列比較は箇条書きではなく**表**にする。走査できるようになる
- 1段落は3〜4行まで。それ以上は分ける
- 冒頭に「結論」を置く。経緯から書き始めない
- コードブロックには必ず言語を指定する

このリポジトリの `docs/` は日本語。既存ファイルの語調（です・ます / である）に合わせる。
