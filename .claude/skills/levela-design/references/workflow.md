# 制作ディレクションの実務

SKILL.md の「作る順番」を実際に回すときの具体。
根っこにある考え方は1つ: **自分は作り手ではなくディレクター**。
制作会社でディレクターがデザイナーに出す指示と、同じ粒度・同じ順番で出す。

---

## 参考の集め方

### 選ぶ基準

| 見る | 見ない |
|---|---|
| 情報の並び順（何を最初に見せているか） | 色 ← Levela固定 |
| 余白の効かせ方・密度 | フォント ← Levela固定 |
| 動きの使いどころ | ロゴまわりの処理 |
| 見出しとサブコピーの主従 | |

**業界が同じ参考は避ける。** 同業を参考にすると構成まで似てしまい、丸パクリの線を越えやすい。
違う業界の「構成が優れたもの」を持ってきて、Levelaの色を当てるほうが安全で、結果も良い。

トンマナが離れすぎた参考を並べるのも失敗する。「余白広めで静か」なら3点ともそうする。
方向がバラバラだと平均値が出てきて、どっちつかずになる。

### 採取の粒度

出力される媒体ごとに現物を見る。**片方しか見ないと、もう片方で必ず崩れる。**

- Web: PC のファーストビュー / PC の中間セクション / スマホのファーストビュー / スマホの中間
- 資料: 表紙 / 本文ページ / 図解ページ

---

## 情報を3回に分けて渡す

一度に全部渡すと、法則性を見失って平均的な出力になる。**前の結論を保ったまま追記させる**のが要点。

```
1回目: 主要面（Webならトップ、資料なら表紙+1枚目）
       → 「この構成・密度を基準にして design.md を書いて」

2回目: 下層・中面
       → 「下層ページの資料も渡す。これを踏まえて design.md を必要に応じて更新して」

3回目: 別媒体（スマホ / 配布版）
       → 「スマホ版も渡す。これを踏まえて design.md を必要に応じて更新して」
```

「必要に応じて」が効く。全部書き直させると1回目の判断が消える。

## 「顔」を3案作る

### なぜ3案か

1案だけだと、良いのか悪いのかを判断する軸がない。3案並べて初めて
「Aの余白とBの見出しが良い」という判断ができる。1案を10回直すより、3案から選んで2回直すほうが速い。

### 3案の振り分け

振り幅を意図的に作る。似た3案を作っても意味がない。

| 案 | 方針 |
|---|---|
| A | **デザイン優先** — 余白と印象を最大化。文言は削ってよい |
| B | **内容優先** — `content.md` のテキストを1文字も省略しない。密度が上がってよい |
| C | **中間** — Aの構図でBの情報量を収める妥協点を探す |

依頼文の型:

```
Levelaのブランド（.claude/skills/levela-design/references/brand.md の確定値）で、
{成果物}の{顔}だけを3案作って。
- 添付: design.md / content.md / 参考の顔スクショ3点
- A: デザイン優先（余白と印象を最大化、文言は削ってよい）
- B: 内容優先（content.md のテキストを省略しない）
- C: 中間
- {顔}より下はまだ作らない
```

### リソースを集中する場所

顔が一番難しく、一番効く。**時間・思考・品質チェックをここに集中させる。**
方向が決まった後の展開作業は機械的なので、そこで力を抜いていい。
逆に、顔が決まらないまま全体を作ると、全部やり直しになる。

## フィードバックの出し方

### 一発で決まらないのが正常

**2周目で品質が跳ねる。** 1回出して「できました」と言うのが最大の失敗パターン。
最低2周は直す前提で予定を組む。

### 悪いフィードバックと良いフィードバック

| ✗ | ○ |
|---|---|
| 「いまいち」 | 「見出しが3行に折れて締まりがない。2行に収まる文字数に詰めて」 |
| 「もっとかっこよく」 | 「セクション間が32pxで詰まっている。64pxに広げて」 |
| 「色を変えて」 | 「サブコピーが `ink-950` で見出しと同じ強さ。`ink-500` に落として主従を付けて」 |
| 「バランスが悪い」 | 「画像とテキストが5:5で緊張感がない。7:3にして左に寄せて」 |

型: **どこが（箇所）・どうダメで（現象）・どうしたいか（指定）** の3点セット。
「どうしたいか」まで書けないなら、それは自分がまだ判断できていないということ。先に判断する。

### まとめて渡す

直しは溜めて一度に渡す。1個ずつ投げると、前の修正が巻き戻る事故が起きる。
5〜10個溜まったら渡す、くらいのリズムが良い。

## 展開のしかた

選んだ1案の方向を保ったまま、**段階的に**広げる。

```
Web:   顔 → 主要面の残り → 下層1ページ → 残り全ページ
資料:  表紙+1枚目 → 章扉1枚 → その章の中面 → 残り全章
図版:  メインカット → 同シリーズ1点 → 残り
```

「下層1ページ」「章扉1枚」を挟むのが要点。
そこで方向のズレを1ページ分の手戻りで発見できる。挟まずに20ページ作ると、ズレたとき20ページ分が無駄になる。

セッションが変わる・コンテキストが切れる場合は、その都度 `design.md` / `content.md` を
渡し直す。渡さないと前提を忘れて別のものが出てくる。

## 素材の扱い

### 構造が先、素材が後

画像はプレースホルダーで進め、レイアウトを確定させてから差し込む。
素材待ちで構造が止まるのが一番もったいない。

### 生成するとき

素材がなければ生成する。外すときは必ずこの2つが抜けている:

1. **参考画像を添付する** — 言葉だけでは狙いが伝わらない
2. **実写かイラストかを明示する** — ここを曖昧にすると毎回違うテイストが出る

人物を入れるなら「非写実的に」を添えると、実在人物に似るリスクを避けられる。

### 命名

配置先が名前から推測できるようにする。

```
hero-main.png
service-01-consulting.png
service-02-training.png
about-team.png
```

こうしておくと「添付の画像を、ファイル名から配置先を推測して置いて」で一括配置できる。
`img_1.png` のような名前だと、1枚ずつ指示する羽目になる。

## 完了の定義

次が全部揃って初めて「できた」:

- [ ] `docs/design.md` と `docs/content.md` がリポジトリにある
- [ ] `references/checklist.md` の該当項目を**実際に確認した**（未確認をOKと書かない）
- [ ] 2周以上の修正を経ている
- [ ] 出力媒体の両方（PC/スマホ、投影/配布）で確認した
